## 1. Architecture et responsabilités retenues

### 1.1 Les pièces

| Pièce | Nature | Dépôt | Rôle |
|---|---|---|---|
| **Kazo OS** | noyau | Kazo-ca/Os | Reçoit des ADR et de petits points d'extension génériques (section 6). Ne connaît ni Wine ni v86. |
| **Os-x86** (`org.kazoos.x86`) | **Feature** de Kazo, installée au niveau système par un admin | Kazo-ca/Os-x86 | Le moteur : fait tourner les VM (v86 dans un Web Worker), fournit les images (Linux avec Wine, FreeDOS), les bouteilles, le stockage des disques, le réseau privé et la sortie par le relais, le partage 9p, l'agent invité, les permissions et le journal. | **`Os-x86.Interface`** | paquet NuGet de contrats | Kazo-ca/Os-x86 | `Ix86` et ses types : lancer et suivre des programmes, exécuter dans une bouteille, ouvrir une console, contrôler les VM (cycle de vie, disques, périphériques, points de restauration), détecter le type d'un fichier, lire l'état des permissions, ouvrir la page des règles. Générique : aucun type Wine. Embarqué dans chaque app cliente ; résolu par `GetServiceAsync<Ix86>()`, null si Os-x86 est absent. |
| **x86-Lib** (`OsX86`) | bibliothèque réutilisable | Kazo-ca/Os-x86 | Implémente `Ix86`. La Feature en enregistre une instance dans Kazo. |
| **BoxedWine** (`org.kazoos.boxedwine`) | app Kazo ordinaire (fenêtre) | Kazo-ca/Os-App-BoxedWine | L'interface : reçoit les lancements Windows par l'association `.exe` (et `.com`, `.bat`, `.cmd`, `.msi`), affiche les programmes Windows, Linux graphiques et DOS graphiques, gère la bibliothèque, les récents, les profils, les réglages des VM de l'usager, l'export. Dépend d'Os-x86 (obligatoire) et de `IBwLib`. |
| **BwLib** (`BoxedWine.Lib`, contrat `IBwLib`) | bibliothèque réutilisable | Kazo-ca/Os-App-BoxedWine | La logique Wine : commandes dans l'invité (`wine`, `wineboot`, `winecfg`, `reg`, `msiexec`), lecture sûre des `.lnk` et des icônes, bibliothèque, profils. Dépend d'`Ix86` seulement. |
| **Images** | artefacts téléchargés | hébergement à choisir (E3) | Alpine x86 + Wine 11.0 + Mono + Gecko + agent + bouteille gabarit en fichiers ; FreeDOS ; sources des composants copyleft à côté. Hors du noyau et du paquet. |

### 1.2 Qui fait quoi (les flux)

- **`./setup.exe` au terminal** (62 B, 154, 162) : le Terminal appelle la détection d'Os-x86 (en-tête, puis extension). MZ+PE console → le Terminal exécute lui-même par Os-x86, sortie dans le terminal, si la redirection de console est livrée ; sinon, et pour tout programme graphique, le Terminal envoie le fichier à BoxedWine par l'association. Le double-clic va toujours à BoxedWine. BoxedWine demande à Os-x86 de lancer : Os-x86 identifie le programme (empreinte, chemin), choisit ou crée la bouteille, applique les permissions, lance par l'agent ; BoxedWine affiche la fenêtre.
- **Programme DOS** (111, 164) : MZ pur au terminal → Os-x86/FreeDOS, texte dans le terminal ; au double-clic ou en mode graphique → BoxedWine affiche ; sans BoxedWine, message et arrêt.
- **ELF** (13) : binfmt par en-tête d'Os-x86 → Linux par défaut de l'usager ; console dans le terminal ; graphique affiché par BoxedWine (§12).
- **Réseau** (D20, D21, 161) : chaque bouteille a son espace réseau et son adresse sur le réseau Ethernet privé d'Os-x86 ; la première connexion réelle non décidée ouvre la fenêtre de permission d'Os-x86 ; la décision, les règles de l'admin et les limites du relais s'appliquent au point de sortie ; nftables dans l'invité en défense en profondeur (à valider, 174).
- **Console et commandes internes** (144, 145, 147, 167) : « exécuter dans la bouteille » pour BoxedWine ; « ouvrir la console » pour l'usager, dans le terminal de Kazo, inaccessible à l'app ; droits de la bouteille partout.
- **VM** (102, 103, 165, 166) : une VM Programmes partagée par genre et par image en V1, utilisée par un usager à la fois ; démarrée à la demande, arrêtée quand sa dernière application se ferme ; démarrée à la main, gardée ; plusieurs VM si la mémoire le permet.
- **Admin** (122, 156, 160) : rôle Kazo déclaré par la Feature ; pages VM et utilisateurs dans Paramètres → Fonctionnalités ; authentification de l'OS à chaque opération sensible ; `sudo x86 …` en ligne de commande.

### 1.3 Ce qui n'est plus dans le plan

Le moteur Boxedwine (GPL), l'app « Sous-systèmes », les fenêtres d'affichage d'Os-x86, la route directe « terminal → Os-x86 » pour les programmes Windows, le repli « VM et DOS seulement » comme fin de V1, la permission « gérer les sous-systèmes » (remplacée par le rôle, 160).

## 6. ADR et changements génériques dans Kazo

Ordre de dépendance ; numéros libres de Kazo à partir de 0243 (vérifié le 2026-11-10). Chaque ADR est une PR dans Kazo-ca/Os, soumise à ses règles, jamais de ma propre initiative (§18). Les issues #431 à #433 sont déjà ouvertes.

### Lot 1 — avant le jalon 0 (socle Feature)

1. **Type d'app « Feature »** (D33, D37, D38, D39) : identité unique, points d'entrée enfants typés, permissions en bloc puis par point d'entrée, installation système seulement, binfmt, pages fournies aux Paramètres.
2. **Bibliothèques d'app et versions partagées** (#419, D30, D36) : DLL NuGet dans le `.kazoapp` ; une copie par nom, la plus récente compatible, choisie au premier besoin ; redémarrage si une copie plus ancienne est chargée.
3. **Registre d'interfaces et résolution asynchrone** (D10, D31) : `GetServiceAsync<T>()`, `IsAvailable<T>()`, `GetStatus`, null jamais mis en cache, permission manquante = exception.
4. **Permissions déclarées par un fournisseur** (D32, 143) : y compris **dangereuses**, traitées comme le catalogue (approbation admin, refus par usager, jamais accordées en silence : corrige #432) ; vérifications par l'écran sécurisé de l'OS même pour une commande.
5. **Rôles déclarés par une Feature** (156, 160) : un rôle réutilisable ; pages de la Feature avec accès à l'agent d'authentification de l'OS ; journal avec app, opération, demandeur.
6. **Résolution des dépendances** par le Store et kazopkg (D12, 72.10) : consentement unique, « demander l'installation », refus = installation cliente arrêtée, retrait = avertissement et désactivation.
7. **Section « Fonctionnalités » des Paramètres** (D38, 122) : liste, pages fournies, élévation.
8. **Persistance et éviction du stockage** : `navigator.storage.persist()` après un geste, détection de l'éviction, OPFS compté dans la réserve.

### Lot 2 — avant le jalon 1 (lancement, terminal, catalogue)

9. **Route du shell vers l'association et binfmt par en-tête** (62 B, 13, 111, 162, 184) : extensions déclarées exécutables, avant le bit d'exécution et la lecture comme script ; binfmt réservé aux Features ; exception de l'app Terminal (détection par Os-x86, exécution directe d'un programme console).
10. **Le Terminal affiche un programme invité** (53, 55, 154, 162, E14) : le Terminal utilise `Os-x86.Interface` comme dépendance facultative (null si absent) ; écran texte et entrée clavier d'un programme console ou DOS dans l'onglet.
11. **Confirmation du gestionnaire par défaut** (D61.10, 124.10) et **catalogue avec formats et dépendances** (D58, §5) : suggestion d'installation par format, sans nom codé en dur.
12. **Expéditeur marqué** pour `LaunchAsync` et l'ouverture de fichier (52, 108) : identité de l'appelant pour le journal et le plafond de 186.
13. **Déclencheurs de tests entre dépôts** (138, §17) : `workflow_call` ou `repository_dispatch` vers Os-x86 et BoxedWine quand Kazo change.

### Lot 3 — jalons 2 à 4 (affichage, processus, entrées, son)

14. **Processus invités** (§12, E7) : processus Kazo visibles pour les programmes d'une VM, arrêt individuel, enfants, limites de l'ADR 0125 attribuées à la VM ; ne repose pas sur `StartChild` (#431).
15. **Icône de fenêtre, marque anti-imitation, entrées du menu Démarrer** (57, 117) : API d'icône (barre des tâches suit), marque de Kazo sur les fenêtres de programmes invités, raccourci avec icône et arguments.
16. **Son** (133, E5) : API audio pour une app ou une Feature ; muet et volume par source.
17. **Tenir le clavier et capturer la souris** (132, 76) : `navigator.keyboard.lock` et `requestFullscreen({keyboardLock})`, touche de libération réservée.
18. **Code de sortie d'une fenêtre lancée du shell** (110) : tenté en V1, obligatoire en V2.
19. **Ctrl+C transmis** à une fenêtre lancée du shell (13, §5) : V2 avec D27, ou plus tôt s'il est petit.
20. **Fenêtres sans propriétaire** (multifenêtre, 112, E4) : conditionnel, après la réévaluation de fin de V1.

### V2

Événements par usager (137) ; contributeurs de sauvegarde (115) ; domaine de synchro d'une Feature (114) ; événement de suppression de compte (131) ; hôtes enregistrés par une Feature (161) ; linger (D45) ; mode brut du terminal (D27).
