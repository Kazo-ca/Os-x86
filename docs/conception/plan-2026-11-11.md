# Plan Os-x86 et BoxedWine — 2026-11-11

Le plan demandé par tes consignes du 2026-11-10 (§20), écrit après la série 11 (« Tu peux commencer le plan »), relu par un relecteur indépendant et corrigé (second jet). Il s'appuie sur le [registre réconcilié](registre-reconcilie.md) (état de chaque décision), le [journal](journal-decisions.md) (chronologie) et les rapports d'essais dans [../essais/](../essais/). Il ne contient aucune nouvelle décision : ce qui n'est pas validé est marqué **à valider** et posé dans la [série 12](serie-12-envoyee.md) (173 à 199). Aucun code de production n'est écrit tant que le plan et les choix bloquants ne sont pas approuvés (§18, §20).

Vocabulaire (200 B) : « bouteille » = `prefix` dans le code, l'API et la commande (`--prefix`, `x86 prefix …`, `Prefix`, `PrefixId`) ; « préfixe » en français dans les nouveaux textes. Les dix points de §20 sont les sections 1 à 10 ; les sections 11 à 13 couvrent les tests, les licences, les conventions et les migrations (§17, §18, §20 dernier paragraphe). Les faits de Kazo viennent du commit `cd89ee0` (relus pour partie sur `main` `6aef3e0`) ; chaque ADR les revérifiera.

### 1.2 Qui fait quoi (les flux)

- **`./setup.exe` au terminal** (62 B, 154, 162, 163) : le Terminal appelle la détection d'Os-x86 (en-tête, puis extension). Programme console → le Terminal l'exécute lui-même par Os-x86, sortie dans le terminal, quand la redirection de console (ADR 10, E14) est livrée ; sinon, et pour tout programme graphique, le Terminal envoie le fichier à BoxedWine par l'association. Le double-clic va toujours à BoxedWine. BoxedWine demande à Os-x86 de lancer ; l'environnement d'exécution identifie le programme et choisit ou crée la bouteille (D50 corrigée ; répartition Os-x86 / BwLib à valider, 193), applique les permissions, lance par l'agent ; BoxedWine affiche la fenêtre.
- **Programme DOS** (111, 164) : MZ pur au terminal → Os-x86/FreeDOS, texte dans le terminal ; au double-clic ou en mode graphique → BoxedWine affiche ; sans BoxedWine, message et arrêt.
- **ELF** (13) : binfmt par en-tête d'Os-x86 → Linux par défaut de l'usager ; console dans le terminal ; graphique affiché par BoxedWine (§12).
- **Réseau** (D20, D21, 161) : chaque bouteille a son espace réseau et son adresse sur le réseau Ethernet privé d'Os-x86 ; la première connexion réelle non décidée ouvre la fenêtre de permission d'Os-x86 ; où la décision et le journal s'appliquent (relais côté Kazo, invité, ou les deux) : à valider, 174.
- **Console et commandes internes** (144, 145, 147, 167) : « exécuter dans la bouteille » pour BoxedWine ; « ouvrir la console » pour l'usager, dans le terminal de Kazo, inaccessible à l'app ; droits de la bouteille partout. Détails : 180.
- **VM** (102, 103, 165, 166) : une VM Programmes partagée par genre et par image en V1, utilisée par un usager à la fois ; démarrée à la demande, arrêtée quand sa dernière application se ferme ; démarrée à la main, gardée ; plusieurs VM si la mémoire le permet. Une VM par genre contre des VM séparées : 194.
- **Admin** (122, 140 B, 156, 160) : rôle Kazo déclaré par la Feature ; pages VM et utilisateurs dans Paramètres → Fonctionnalités **dès le premier jalon** ; authentification de l'OS à chaque opération sensible ; `sudo x86 …` en ligne de commande.

### 1.3 Ce qui n'est plus dans le plan

Le moteur Boxedwine (GPL), l'app « Sous-systèmes », les fenêtres d'affichage d'Os-x86, la route directe « terminal → Os-x86 » pour les programmes Windows graphiques, le repli « VM et DOS seulement » comme fin de V1, la permission « gérer les sous-systèmes » (remplacée par le rôle, 160), tout plafond de permission fondé sur l'app qui lance (108).

## 13. Stockage, migrations et protection des données (§20)

- **Formats versionnés** : chaque disque, couche, bouteille, profil et point de restauration porte un numéro de format et la version d'image et de moteur qui l'a produit (D44, D56). Un état de veille est lié à la version de v86 (STATE_VERSION) et est jeté, jamais migré (D34).
- **Migration** : Os-x86 lit les formats de la version majeure précédente et les convertit à l'ouverture, après un point de restauration automatique (188) ; une conversion impossible refuse d'ouvrir et le dit, sans écrire (169).
- **Protection** : aucune mise à jour d'image ou de Feature n'écrit dans une bouteille sans point de restauration préalable ; un seul écrivain par disque (E11) ; `flush()` périodique et à l'arrêt (177) ; éviction détectée = avertissement et proposition d'export (177) ; la désinstallation garde les données (D11) ; la suppression d'un compte suit 131.
- **Ce qui n'est pas protégé, à dire dans la spécification** : une réinitialisation d'usine de Kazo efface l'OPFS ; Safari efface le stockage après 7 jours sans interaction (E10) ; le JavaScript d'une app Kazo de la même origine peut lire le stockage (D61.1, 182).
