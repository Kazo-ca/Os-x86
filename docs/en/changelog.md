# Os-x86 changelog

## Unreleased (0.1.0, milestone 0)

- Repository scaffold on the `kazoos-solution` template of Kazo OS: Kazo OS submodule pinned on `v3.2.1`, projects `OsX86.Interface`, `OsX86`, `OsX86.Feature`, host `OsX86.Os`, tests, CI.
- `x86` command (`--version`, `vm list`) and `Ix86` contract (version, VM list).
- App identifier: `ca.kazo.x86` (decision 222 A, replaces `org.kazoos.x86` of 172 A); `org.kazoos.` stays with the built-in apps of the Kazo OS repository.
- Engine (work item 2): v86 0.5.473 vendored in `src/OsX86/wwwroot/v86` (BSD-2, SeaBIOS LGPL-3, script `tools/v86/vendor-v86.py`, patch #1661 ported), Web Worker `v86-worker.js` and host module `v86-host.js`, `IEngine` abstraction with `V86Engine` (states stopped, starting, running, paused, stopping; coded errors), serial and virtio-console ports read raw or by lines and written, OffscreenCanvas bridge, Alpine test image (`images/alpine-test`, verified official ISO, never committed) read from the OPFS, `unit` tests (80 % coverage required by the CI) and `guest` test (Playwright, `guest-tests.yml`). See [`engine.md`](engine.md).
- Storage (work item 3): image manifest reader and validator (`ImageManifest`, format 1, an unknown format refused without writing anything, expected SHA-256 compared first), Web Worker `storage-worker.js` and host module `storage-host.js` (`fetch` with `no-store`, SHA-256 per chunk with `SubtleCrypto`, OPFS writes through a `FileSystemSyncAccessHandle`, resume state `download.json`, retries with a growing delay, cancellation, progress in bytes, chunks and rate), `ImageStore` with `JsStorageWorkerChannel` (download driven by the `ResumePlan` computed in C#, list, delete, `estimate()`, in-place verification, OPFS path of a logical file), repository `osx86/images/<image>/<version>/` with versioned metadata `image.meta.json` (`StoredObjectMetadata`), write lock through `navigator.locks` and `flush()` after every chunk, every 5 s and at close; `unit` tests and an 800 MiB `guest` test with 503s and cuts (`ChunkImageServer`, image generated on the fly, never committed); `guest-tests.yml` also triggered by the storage paths. See [`storage.md`](storage.md).
- Images (work item 4): `images/tools/pack-image.py` tool (entries as zstd "seekable" streams with 1 MiB frames, 32 MiB chunks, `manifest.json` format 1 and `manifest.sha256`, `check`, `extract`, `info` modes); `images/linux-base` recipe (slimmed Debian trixie-slim i386, Alpine `linux-virt` 6.18 kernel through `apk fetch`, ext4 root on `hda`, minimal init with serial console and four virtio-console ports, place of the agent, 210 A hardening, package and license inventory); `images/alpine-test` packed; `images/freedos` recipe (pinned official 1.4 archive, text prompt); image test `images/tools/image-check.py` (writable inventory and static counterparts of the 22 R134.5 checks, `verify-console.sh` kept in the image); `sources.json` per image (`snapshot.debian.org` addresses, Alpine APKBUILD); `images.yml` workflow (path-triggered builds, artifacts, Pages behind `OSX86_PUBLISH_PAGES`, R2 behind `OSX86_R2_*`, never run); `unit` tests of the tools and `guest` test of the Alpine pack. Sizes: alpine-test 15.1 MB, freedos 17.2 MB, linux-base 73.0 MB. See [`images.md`](images.md).
