# Os-x86 changelog

## Unreleased (0.1.0, milestone 0)

- Repository scaffold on the `kazoos-solution` template of Kazo OS: Kazo OS submodule pinned on `v3.2.1`, projects `OsX86.Interface`, `OsX86`, `OsX86.Feature`, host `OsX86.Os`, tests, CI.
- `x86` command (`--version`, `vm list`) and `Ix86` contract (version, VM list).
- App identifier: `ca.kazo.x86` (decision 222 A, replaces `org.kazoos.x86` of 172 A); `org.kazoos.` stays with the built-in apps of the Kazo OS repository.
- Engine (work item 2): v86 0.5.473 vendored in `src/OsX86/wwwroot/v86` (BSD-2, SeaBIOS LGPL-3, script `tools/v86/vendor-v86.py`, patch #1661 ported), Web Worker `v86-worker.js` and host module `v86-host.js`, `IEngine` abstraction with `V86Engine` (states stopped, starting, running, paused, stopping; coded errors), serial and virtio-console ports read raw or by lines and written, OffscreenCanvas bridge, Alpine test image (`images/alpine-test`, verified official ISO, never committed) read from the OPFS, `unit` tests (80 % coverage required by the CI) and `guest` test (Playwright, `guest-tests.yml`). See [`engine.md`](engine.md).
- Storage (work item 3): image manifest reader and validator (`ImageManifest`, format 1, an unknown format refused without writing anything, expected SHA-256 compared first), Web Worker `storage-worker.js` and host module `storage-host.js` (`fetch` with `no-store`, SHA-256 per chunk with `SubtleCrypto`, OPFS writes through a `FileSystemSyncAccessHandle`, resume state `download.json`, retries with a growing delay, cancellation, progress in bytes, chunks and rate), `ImageStore` with `JsStorageWorkerChannel` (download driven by the `ResumePlan` computed in C#, list, delete, `estimate()`, in-place verification, OPFS path of a logical file), repository `osx86/images/<image>/<version>/` with versioned metadata `image.meta.json` (`StoredObjectMetadata`), write lock through `navigator.locks` and `flush()` after every chunk, every 5 s and at close; `unit` tests and an 800 MiB `guest` test with 503s and cuts (`ChunkImageServer`, image generated on the fly, never committed); `guest-tests.yml` also triggered by the storage paths. See [`storage.md`](storage.md).
- Images (work item 4): `images/tools/pack-image.py` tool (entries as zstd "seekable" streams with 1 MiB frames, 32 MiB chunks, `manifest.json` format 1 and `manifest.sha256`, `check`, `extract`, `info` modes); `images/linux-base` recipe (slimmed Debian trixie-slim i386, Alpine `linux-virt` 6.18 kernel through `apk fetch`, ext4 root on `hda`, minimal init with serial console and four virtio-console ports, place of the agent, 210 A hardening, package and license inventory); `images/alpine-test` packed; `images/freedos` recipe (pinned official 1.4 archive, text prompt); image test `images/tools/image-check.py` (writable inventory and static counterparts of the 22 R134.5 checks, `verify-console.sh` kept in the image); `sources.json` per image (`snapshot.debian.org` addresses, Alpine APKBUILD); `images.yml` workflow (path-triggered builds, artifacts, Pages behind `OSX86_PUBLISH_PAGES`, R2 behind `OSX86_R2_*`, never run); `unit` tests of the tools and `guest` test of the Alpine pack. Sizes: alpine-test 15.1 MB, freedos 17.2 MB, linux-base 73.0 MB. See [`images.md`](images.md).
- Guest agent (work item 5): static musl i386 C agent in `images/agent` (non-blocking `poll` loop, JSON lines with `id` on `hvc0`, `ready`, `exit`, `open-url`, `console-closed` events; `ping`, `list-processes`, `launch`, `kill` by launch identifier or by `scope`, `mounts`, `exec-in-prefix`, `open-console`, `close-console`, `console-resize`, `list-windows` as a stub; one cgroup v2 per launch, `RLIMIT_NPROC`, user `osx86-<prefix>`, never a shell; pty consoles multiplexed on `hvc1` by frames, exit code on the same channel; `osx86-open-url` through a unix socket and `SO_PEERCRED`), `build-agent.py` recipe (pinned Alpine stage, `--check`, `--smoke`), installation in linux-base (checked in the export, `agent_files_root_only` check of the image test) and in the Alpine test image (two prefix users, cgroup v2); C# client `src/OsX86/Agent` (`AgentClient`, `IAgentChannel` and `EngineAgentChannel` on `virtio0` and `virtio1`, pairing by `id` with a timeout, event stream, `LaunchId`, `ProcessInfo`, `MountInfo`, `ConsoleHandle`, typed errors); `unit` tests (simulated channel) and `guest` test (the Alpine image driven from C#); `guest-tests.yml` and `images.yml` build the agent, i386 seccomp repair as a shared script. See [`agent.md`](agent.md).
- Kazo OS pinned on `v3.4.0` instead of `v3.2.1` (decision 266 A: follow the prereleases that bring an ADR of the Os-x86 series, then the stable version when it is released; 3.4.0 was released the day of the decision); no code change needed, the `OsX86.Feature` manifest now requires SDK `3.4.0`. See [`README.md`](README.md#kazo-os-version).
- Disks and boot from the manifest (work item 6a): `zstd-seekable.js` and `disk.js` in the engine worker (seek table read once, frames decompressed on demand by the zstd decoder of `v86.wasm` in its own instance, bounded and measured LRU cache); persistent write layer `osx86/layers/<set>/<disk>.layer` (format 1 header, map of 4 KiB blocks, `.meta.json` of kind `layer`, `navigator.locks` lock, `flush()` every 5 s, at pause and at stop) or discard; `ImageStore.ListLayersAsync` and `DeleteLayersAsync`; `EngineStartOptions` with `Kind`, `Kernel`, `Initrd`, `Disks`, `FrameCacheMiB`; `ImageBoot.CreateStartOptions` from the `boot` section (`ImageBootSection`, `rawSize` and `blockSize` of the files) and the same-major-version rule (`engine-version-mismatch`, 169); `V86Engine.ReadTextScreenAsync` and `GetDiskStatisticsAsync`; fix of the lost `ready` of `JsEngineWorkerChannel`; image recipes in LF (a CRLF checkout left the linux-base initramfs without `sd_mod` and `ext4`), `/dev` of linux-base in its usual modes, `verify-console.sh` correct under `hidepid`; `unit` tests (including `disk-tests.js` under Node) and `guest` tests (linux-base: agent, 22 R134.5 checks, persistent then discard layer; FreeDOS to its prompt), `guest` job in `images.yml`. See [`engine.md`](engine.md).
- VMs and command (work item 6): `.x86profile` profiles in format 1 (`VmProfile`, opaque "programs" section for BoxedWine, shipped `alpine-test` and `linux-base` profiles); VM registry by stable user identifier (`VmRegistry`, versioned `VmRegistryDocument`, kept by the command in `~/.config/ca.kazo.x86/vms/<guid>.json`, `filesystem.private.read` and `.write` declared); `VmManager` and `VmInstance` (start on demand by the first application, application count, stop after a configurable 5 s grace, start by hand kept, stop refused then forced, guest death, one engine per run from an injectable factory, `AgentClient` connected, launches and consoles tracked as children, agent watchdog pinging every 20 s and lost after two misses, serial console fallback for an image without agent); memory limit (`MemoryBudget`: half of the announced memory or the administrator's limit, `VmMemoryBudgetExceededException` refusal with the running and compatible VMs, atomic check); `x86 vm list|create|start|stop|remove|rename|info`, `x86 shell` (the agent's console relayed to the terminal line by line, echo removed, Ctrl+C and a `^C` line to the guest, `~.`, exit code returned) and `x86 profile list|show|import|export`, stable exit codes; `Ix86` extended (state and event, start, stop, `OpenConsoleAsync` and `IVmConsole`, `X86Exception`) with `PublicAPI.Unshipped.txt`; `unit` tests (simulated engine and agent, manual clock) and a `guest` test (`x86 vm create` then `x86 shell` on the Alpine image with the agent in a real browser); `guest-tests.yml` also triggered by the VM layer and the Feature. See [`vm.md`](vm.md).
- `linux-base` by default (work item 6b): `X86Command.DefaultProfile` on `linux-base`, `alpine-test` kept as the test profile; catalog of the known images (`ImageCatalog`, `KnownImage`: identifier, version, manifest address, expected hash, format 1); `StoreBootImageSource` on `ImageStore` (a complete image is used, a missing or partial one is downloaded and verified by the storage worker, progress raised by `VmManager.ImageProgress` and written by `x86 shell` and `x86 vm start`, one download at a time); `BootImage` extended to stored images (`ImageStore.Locate` for kernel, initramfs and disks, start through `ImageBoot.CreateStartOptions`); `IBootImageSource.ResolveAsync` with progress and `DeleteLayersAsync`; one persistent write layer per VM (`VmRecord.LayerSet`, `vm-<guid>`) deleted by `x86 vm remove` (new error code `storage-failed`); `x86 shell` without prefix on a profile that declares a serial port opens the root serial console, with a notice; `VmHost.Configure`, `VmHost.ForBrowser` and `JsEngineFactory`: the dev host `OsX86.Os` gives the command the engine, the storage and the packs built in `images/build/` (`DevImages`, hash of the `manifest.sha256` recorded by the build); `unit` tests and the `guest` test `X86ShellLinuxBaseGuestTests` (download from a local origin, file kept after the stop and erased with the VM; first and second `x86 shell` in 16 s); the command runs on Kazo's main thread (`execution: mainThread`) and creates its private directory the way Kazo's settings do (the first `x86 vm create` of a user was refused in Kazo before). See [`vm.md`](vm.md#linux-base-by-default-work-item-6b).
- Flaky tests of the VM layer (work item 6c): `AgentClient.ConnectAsync` accepts the late reply to an earlier `ping` (an agent slower than the probe interval was declared absent, hence `no-console` instead of `agent-error` on loaded runners); the VM test rig keeps the short connection delay for images without agent only.
