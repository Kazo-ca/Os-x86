# Essai E3 — distribution des images (code jetable)

Téléchargement reprenable par morceaux (`Range` → `SubtleCrypto.digest` → OPFS `createSyncAccessHandle`) d'un fichier de 800 Mio généré, avec coupures simulées, limite à 100 Mbit/s, avec et sans COOP/COEP ; `fetch` d'un seul tenant avec `integrity` ; lectures `Range` à la demande ; cache HTTP et Cache API ; SHA-256 en .NET WebAssembly (Blazor, `dotnet/`) contre `SubtleCrypto` et JS pur ; sondes HEAD/Range sur des hébergeurs publics (`probe-hosts*.sh`). Résultats commentés dans `docs/essais/e3-distribution.md`.

Pour relancer : `npm install` ; `node gen.mjs --size 800` et `node gen.mjs --size 200` (fichiers et manifestes SHA-256 dans `images/`, gitignoré) ; `cd dotnet && dotnet publish -c Release -o publish/interp` puis mettre `<base href="/dotnet/interp/" />` dans `publish/interp/wwwroot/index.html` ; `node run.mjs` (options `--browsers chrome,msedge,firefox`, `--runs 3`, `--only chunk,resume,throttle,whole,range,coi,cache,cors,hash,dotnet`, `--size`, `--port 8098`). `node server.mjs` seul sert `dl.html` pour un essai à la main (`/ctl?cut=20&cuts=3&skip=5&fail503=2&rate=100&coi=0`, `/stats`). `node tableau.mjs` résume `resultats/results-*.json`. Chaque passe part d'un profil de navigateur neuf, supprime son fichier OPFS et le profil. Les fichiers de 800 Mio sont supprimés à la fin de l'essai (`images/` vide) : regénérer avec `gen.mjs`, le contenu est déterministe (même SHA-256).
